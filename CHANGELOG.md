# Changelog

## Versions and what a tag promises

- **Version numbers.** While silkify is 0.x, a minor release (0.4) may rename or remove options and handle members; it says so here. A patch release (0.3.1) fixes and adds, and never breaks a `silkify()` call that worked: the default look stays pixel for pixel the same (the gallery posters are re-rendered and compared byte for byte before a release).
- **Tags.** A release tag (`v0.3.0`) is pushed once, after every check has passed on that commit, and is never moved or deleted. That is this project's promise, not a property of git: a tag can be force-pushed.
- **Copying `src/` is the default, and the safest.** A page that serves its own copy changes only when you copy a new release in, and depends on no outside service.
- **If you import from the CDN instead,** jsDelivr keeps the files it has served for a tag, so `@v0.3.0` does not change under a page in practice, but nothing cryptographic guarantees it. When integrity matters, pin a commit: `https://cdn.jsdelivr.net/gh/RussGuo/silkify@<40-character commit SHA>/src/silk.js` names exactly one tree of files.
- **Subresource Integrity covers one file.** On the CDN, an `integrity` attribute (or an import map's `integrity` entry) checks only the module the page imports directly, silk.js. The modules silk.js imports, the worker it starts, and three.js loaded inside that worker are fetched without one. For the whole chain, copy `src/` and serve it yourself.

## Unreleased

**Added**
- **Words as the object.** `silkify(canvas, { text: 'silk', font: '800 200px Georgia, serif', color, lineHeight })` makes a word, a headline, a letter or an emoji the object, with no picture and no cut-out. The text is set in a canvas once its font has loaded (up to 3 s) and is then a picture like any other: it inflates, dents and ripples in every material and feel, and the static tier draws it flat. Lines split on `\n`; colour emoji keep their colours; CJK falls back glyph by glyph. By default the words take the canvas's CSS `color` and a heavy weight of its `font-family`. A font that is not there falls back down the stack as in CSS. silkify warns only about what the page can fix, once, with `console.warn`: a declared web font (`@font-face`, a `<link>`) that failed or did not arrive, or a stack with no generic family none of whose fonts is there. A system font missing on the visitor's machine, in a stack that ends in `serif` or `sans-serif`, is quiet. Mistakes in the call (text with `image` or `element`, an empty text, an unreadable font or colour) throw a `TypeError`. New file `src/text.js`; `examples/text.html`; `test/text.html`, run by `scripts/shoot.mjs`. See references/parameters.md, "Text".
- **Words in the Lab.** Object → Words: a text box (several lines too), a font (four system stacks and three Google Fonts, Noto Serif SC among them, whose stylesheet is added only when picked), a weight, a colour, and the line height once there is a second line; material, feel and every Advanced option work as for a picture. The link, Copy options and Download HTML carry `text`, `font`, `color` and `lineHeight` (a downloaded page with a Google Font has the same `<link>` and waits for it; until a release has words, it imports silk.js from `@main`). `scripts/shoot.mjs` checks the round trip, the printed call and the downloaded page.
- **Record a clip in the Lab.** Record makes a 3 or 5 s video of the object, square or 9:16, while a scripted stroke and touch play or while you touch it yourself; the canvas takes the clip's shape and background while the panel is open, so the stage shows what the clip will. MP4 (H.264) where the browser records it (Chrome, Safari), WebM elsewhere (Firefox); a browser without MediaRecorder shows no Record button. A small "silkify · github.com/RussGuo/silkify" mark sits in the corner, on by default, one click to leave out. A still frame (the static tier, reduced motion) has nothing to record and the panel says so. `scripts/shoot.mjs` records a square and a 9:16 clip and checks the type, the size and the shape.
- **Link previews.** The gallery, the Lab, `examples/live.html`, `examples/text.html`, `examples/button.html`, the long read in both languages, the four use-case pages and the site's root carry Open Graph and X (`twitter:card`) tags with a picture, `docs/og.jpg` (the README's hero cropped to 1200 × 630, a JPEG because some chat apps do not show WebP), so a shared link unfurls with the pomegranate instead of a bare URL.
- **A word in the gallery.** The fourth card is "silk" in Fraunces Black, gold foil: no picture at all, `{ text: 'silk', font: '900 160px Fraunces', color: '#8a6d3b', material: 'foil' }`. Its font is a 1.4 KB subset in the repository (`examples/fonts/`, SIL Open Font License), declared with `@font-face` and fetched only when the card comes alive; its poster is new, and the other twenty posters are the same files.
- **How silkify works**, a long-form page in English and Chinese (`examples/how-it-works.html`, `examples/how-it-works.zh.html`): the Poisson dome, the Moon's light, silk only where it ripples, waves held inside the outline, the renderer that sleeps, and live HTML, each told first as what you see and then why. Seven figures, four of them interactive (distance field against the Poisson dome; Lambert against Lommel–Seeliger; the wave-energy mask on and off; the ripple field with its wall on and off); the drawn ones redo the library's own maths, `src/shape.js` itself for the dome. The live figures follow the gallery's budget (posters first, mounted in view, disposed out of view, at most 3 at once); with reduced motion or without WebGL2 every figure has a still form. Posters by `examples/how/posters.mjs`. Linked from the gallery, the Lab, the READMEs and `references/how-it-works.md`.
- **Use cases.** Four pages to start from in `examples/demos/`, each one HTML file: a product hero (`hero.html`), a logo wall of twelve marks with posters first and at most three live (`logo-wall.html`), a full-bleed section as one sheet of silk (`fabric.html`) and a 404 with numerals to poke (`404.html`). Light and dark, 375 px to 1440 px, still pictures under reduced motion. Linked from the gallery and the READMEs; SKILL.md lists them as templates.
- **Events** (#18). `onPress({ x, y, pointerType })`, `onRelease({ x, y, over, held, pointerType })` and `onStroke({ x, y, dx, dy, pressed, pointerType })` (at most every 100 ms) report the pointer on the canvas, also while the renderer loads; `onReady(handle)` and `onFail(handle)` say how the object settled, and a lost WebGL context now calls `onFail` (then `onReady` when it is live again), so a page no longer has to poll `handle.mode`. They are options, like `onHover`, not DOM events, because the canvas element is replaced on a fallback or a lost context. A callback that throws is reported as an uncaught error and stops nothing else. In live HTML a press on a link, a button or a field inside the element is that control's and is not reported. `haptics: true` adds one 10 ms vibration on a touch or pen press where the browser can, after the page's first user gesture; off by default. New file `src/events.js`; the React and Next.js components pass the events as props; the gallery counts presses per card through `onPress` (`?debug` logs them). `test/events.html` and `scripts/verify-events.mjs`, run by `scripts/shoot.mjs`. See references/parameters.md, "Events".
- **The silk button** (#18), `examples/button.html`: a real `<button>` whose face is a silk object. Mouse and touch dent it, Enter and Space ripple it from the centre (`handle.ripple()`), its focus ring is the page's own, its action is the button's `click`, and in the static tier it works the same with the poster as its face. SKILL.md describes the pattern; `scripts/shoot.mjs` presses it with a mouse, a finger and the keyboard.
- **`prewarm(options)`** (#1): starts one worker and has it import three.js before any object mounts, so a page that mounts objects on their first touch only waits for the scene: `activate()` → `ready` in the gallery went from 1.2–1.4 s to about 0.12 s (headless Chrome, fresh context). The gallery prewarms once the page is idle. See references/performance.md, "Many objects on one page".
- **`fit: 'cover'`.** The object fills the canvas whatever their proportions, cropped on the long axis like CSS `object-fit: cover`, and follows the canvas when it is resized, with no new `silkify()`. For a section whose background is one sheet of silk (`matte: 'rect', corner: 0`, a low `puff`); `examples/demos/fabric.html` now mounts once instead of painting and mounting again whenever the section's proportions change. The static tier draws the picture the same way. A `fit` that is neither a number above 0 nor `'cover'` throws a `TypeError`, and so does `'cover'` with `element`.
- **A poster the page draws.** `poster` also takes a canvas, or a function `({ width, height }) => canvas or img` (or a promise of one) that is called with the canvas's size in device pixels whenever a still frame is drawn: in the static tier, under reduced motion, while a lost WebGL context is away, and again after a resize. A page that paints its own picture (`examples/demos/fabric.html`'s cloth) no longer wires a still frame by hand. A function that returns nothing drawable ends in `mode: 'failed'` with a reason.
- **`breezeIdle`.** `breeze` kept the loop at 30 fps for as long as the object was in view. `breezeIdle: ms` stops it once nobody has touched the object for that long (from the mount, the last touch or pointer over it, `handle.wake()`, or a new `breeze` value); the loop then takes its tail and rests, and a touch or `wake()` starts the breeze again. Off by default. Off-screen and in a hidden tab a breezing object already drew nothing; `test/options.html` now checks that too. `examples/demos/fabric.html` uses `breezeIdle: 20000`.
- **`pool()`, the many-objects pattern, from the library** (`src/pool.js`). Poster first, live on the first `pointerenter` or `pointerdown`, disposed when it scrolls away, at most `max` live (the least recently touched released), prewarmed once the page is idle, nothing at all in the static tier: `const wall = pool({ max: 3 }); wall.add(el, (canvas) => silkify(canvas, options))`. The gallery and `examples/demos/logo-wall.html` used to write it out by hand; both use it now (the logo wall prewarms now too), and the gallery's posters are the same files. **`coolDown()`** (silk.js) lets the worker `prewarm()` keeps idle go and stops warming new ones; `pool().dispose()` calls it. `test/pool.html` checks both.
- **Where a press lands on the object.** `onPress`, `onRelease` and `onStroke` carry `uv`: `[u, v]` on the object itself (a picture's box, the words' ink, a sphere's map as it is turned), or `null` off the object. The renderer answers it (its camera and `fit`, `'cover'` included), so the three callbacks now come a moment after the gesture (the worker answers between frames), in order; a press while the renderer loads is reported at once with `uv: null`. `test/events.html` checks it.

**Changed**
- **Breaking: `fit` is checked.** A `fit` that is neither a number above 0 (or a string of one, such as `'1.5'`) nor `'cover'` now throws a `TypeError`; before, `fit: 0` or `fit: 'abc'` mounted an object scaled to nothing. A `text` option passed together with `image` or `element` (meaningless before 0.4) also throws. Every other 0.3 call works as it did.
- **The gallery and the READMEs open with the Mona Lisa and the pomegranate**, then the moon; the FateTell ink drop moves to the end of the objects (its notice is unchanged). The Lab's object list follows. Only the order changed: the posters are the same files.
- **Who made it, wherever it travels.** A line under both README titles, the gallery's footer and the Lab now say "Made by Russ Guo" with a link; a file downloaded from the Lab carries the same credit in a comment and a small "silkify" link in its corner. The name and links live in one place, `scripts/build-integrations.mjs`, which writes them into every page and fails `--check` when one drifts.
- **The READMEs lead with what silkify is and how to try it:** install, the 30-second start (now with the React component and a pointer to words as the object), materials and feels, the gallery, live HTML, then browsers and fallbacks in three bullets (where "What it is not" went). Material moved, none removed: How it works and the performance overview are in `references/how-it-works.md` (and `.zh-CN.md`), the Lighthouse history in `references/performance.md`, the repository layout and the rules for a change in `CONTRIBUTING.md` (and `.zh-CN.md`); the option table and the live-HTML details are folded under the sections they belong to.
- **Every control in the Lab says what it does.** Each row shows a plain name with the API name beside it ("Press depth · `pressDepth`") and, under it, one line from `references/parameters.md` (generated into `examples/lab-help.js` by `build-integrations.mjs`, so the two never disagree), readable on touch screens. Every input now has an accessible name: the label is tied to the row's main control and describes it, the number boxes and the other inputs have their own; an axe-core audit of the Lab reports no unlabelled form controls and no contrast failures at 1280 and 375 px. `references/parameters.md` gained the missing line for `bumpStrength`.
- **The Lab opens on the look.** Object, material and feel sit at the top of the panel, with your own picture and the background just below; every other option is under **Advanced**, closed unless the link already carries values beyond the object's own. The renderer's readout (tier, thread, grid, fps, loop state) shows only with `lab.html?debug`; a still frame or a failure still says why. The stage's hint and its buttons share one row that wraps instead of overlapping, and at 375 px the object has its own box between the title and the buttons.
- **One set of pointer listeners for the whole page** (#9). Each object used to add its own window listeners and read its canvas's position on every pointer move, so a grid of 20 objects did 20 handlers and 20 layout reads per move. Now every object shares one set (`src/pointer.js`), and a canvas's position is read only when it is near the viewport. Behaviour is unchanged: only the object under the pointer is woken.

**Fixed**
- **A Lab link can no longer put code into what the Lab prints or downloads** (in every release so far). The link's state was read as it came, and Copy options and Download HTML wrote its values into code with a quote swap and no escaping, so a value such as `exposure: "1'+(…)+'"` came out as a live expression: whoever pasted the printed call into a project, or opened the downloaded page, ran the link author's code. The Lab now keeps only what its own controls could have set (known keys, each of its control's type and range, a font and a colour the browser can read, a picture at an http(s), blob:, data:image or relative address; `examples/lab-state.js`), and writes every value through one serializer that escapes quotes, line breaks and `<`, so nothing can close a string or the downloaded page's `<script>`. `scripts/verify-lab.mjs` opens links that try a closing quote, `</script>`, a template string, a line break and a `javascript:` picture, and runs the printed call and the downloaded script: nothing in the page changes.
- **The first touch is no longer lost while an object mounts** (#1). silkify listens to the pointer from the call on, not from `ready`: a pointer still over the canvas when the renderer is up hovers and presses at once, and one that has already gone (a stroke across, a tap) gets one ripple where it first crossed the object. Before, everything the pointer did in the half second or more of loading was dropped, so in the gallery the first stroke across a card did nothing. `test/first-touch.html` checks a hover, a stroke, a tap and a held button made while loading.
- **The gallery on a phone shows that its objects are alive** (#2). On a touch screen the hint (`touch · hold to press deeper`) stays visible instead of waiting for a hover that never comes; the first time a card is mostly in view it mounts and plays one ripple (not in the static tier, so not with reduced motion; still at most 3 live); in the static tier, whose posters do not move, the hint is not shown at all; and a first tap on a card that is still a poster dents it once it mounts, through the pointer kept while loading. Checked at 375 px with touch emulation: the tap is compared with the same card mounted untouched.
- **A quick tap dents the object** (#2). A finger that comes down and lifts within one frame (a quick tap on a phone) left no dent and no ripple, because no frame ever saw it pressed; such a press now becomes one touch where it landed, as deep as a held press. `scripts/shoot.mjs` taps a live gallery card with the down and the up in one task, at 375 px, and compares it with the pointer merely passing.
- **A lost WebGL context no longer leaves a blank or frozen canvas** (#6). Browsers take contexts back (a phone reclaiming GPU memory from a background tab, a driver reset, more contexts than they allow); nothing listened, so the canvas stayed blank (main thread) or frozen on its last frame (worker) and `mode` still said `'webgl'`. Now the object shows its poster or picture at once on a fresh canvas (a live element goes back to the page as plain HTML), `mode` turns `'static'` with a `reason`, and when the context is restored the renderer is rebuilt behind the still frame and `mode` is `'webgl'` again. Read `handle.canvas` after it: the element is replaced. `test/lost.html`, run by `scripts/shoot.mjs`, loses and restores the context (`WEBGL_lose_context`) for a picture in a worker, with a poster, on the main thread, for words and for a live element. references/performance.md describes the context budget.
- **The Lab's Touch and Stroke land on words.** Their points were fixed near the middle of the canvas (y 0.42 → 0.61), which for two lines of words is the gap between the lines: every drop missed and the buttons, and Record's "A stroke", did nothing. For words they now go onto the ink: each point to the middle of the nearest line, then to the nearest inked pixel there, so a stroke runs along the first line, then the second. A picture's stroke is unchanged.
- **A sphere keeps its outline when it is pressed.** The moon's surface moved along its normals, so a press or a stroke near the limb pushed the outline out and pulled it in (the disc visibly bulged), and at the poles, where a whole row of vertices is one point with a different height each, the point opened into a small spike at the top and bottom edges. A sphere now moves along the line of sight, as a picture's dome always has: every vertex stays where it is on screen and the ripples show through the light alone. At rest nothing moves, so the posters are the same files. `scripts/verify-options.mjs` presses a sphere hard at its limb and poles and counts the pixels outside its rest outline: 0 (thousands before).
- **`corner: 0` is a square.** With `matte: 'rect'`, `corner: 0` put every pixel exactly on the outline, half covered, so none counted as inside and the mount failed with "nothing opaque in it" (the fabric use case had to write `corner: 0.002`). The rectangle's distance is now signed inside too; any corner of half a pixel or more draws exactly as before. `test/options.html` checks it.
- **`fit: '1.5'` works again.** The new check on `fit` refused a number written as a string, which 0.3.0 accepted (a value read from a data attribute or a form); it is now read as that number. `test/options.html` checks it draws exactly as `fit: 1.5`.
- **A WebGL context lost while the object is still loading.** The renderer listened for a lost context only once three.js had loaded, so a loss before that was never answered: the browser could not restore it, and the object either claimed `'webgl'` on a dead context (worker) or ended in a still frame blaming three.js (main thread). A loss and a restore that both came while it loaded were ignored, leaving the object a still frame for good. Now the context is watched from the moment it exists: a loss while loading settles `ready` as a still frame (`mode: 'static'`, the lost-context reason, `onFail`), and the restore rebuilds it, also when it came before the mount had settled. `test/lost.html` loses the context at fixed points of the loading (before three.js, and while the picture decodes, with and without a restore), twice in a row once live, and once before `dispose()`.
- **`pool()`: a `mount()` that throws no longer leaks a canvas.** Each `pointerenter` left one more empty canvas in the element and threw again. Now the canvas goes, `activate()` rejects with the error, and a pointer reports it once as an uncaught error (like a callback that throws) without trying that element again; a `mount()` that returns no handle rejects too.
- **A poster function that throws says so.** It ended in `mode: 'failed'` with "the poster function returned null" and the error swallowed; the reason now says it threw and why, and the error is reported as an uncaught error. A `poster` (or `image`) that is an `<img>` still loading is waited for instead of drawing an empty frame, and one that cannot load fails with its URL in the reason.
- **`handle.info`** no longer carries the message tag `t: 'ready'`; it is `{ tier, software, sim, steps, mesh, texture, ratioCap }`, as SKILL.md now says. `stats()` adds `touches`, the touches the renderer has made (`ripple()`, `autoplay`, a tap too quick for a frame).
- **Small type reads at 4.5:1 everywhere.** The Lab already used a darker grey for its small type; the gallery, the long read in both languages and the text, button and live-HTML pages still set it in `#7a746a` on paper (4.0:1) and their small accent type in `#8a6d3b` (4.2:1). They now use the use-case pages' `#6f695f` and `#7a5f30` in light mode (dark mode passed already). `scripts/verify-pages.mjs` measures every piece of text on a plain colour in those pages and the Lab, light and dark.
- **The Lab no longer shows options that do not apply.** A row marked hidden (the moon's phase, relief and spin for a picture) was still drawn, because the row's own CSS overrode `hidden`.

Pictures look the same: the posters re-render byte for byte.

## 0.3.0 (2026-11-19)

**Added**
- **Live HTML.** `silkify(canvas, { element })` prints a real element on the silk instead of a picture, through HTML-in-Canvas (Chrome 157 and later). The element stays HTML: its words can be selected, copied and found, links and buttons work, editable text takes typing and input methods, it scrolls, screen readers read it, and the silk still dents and ripples. It is drawn 1:1 by default, at the place the page laid it out, and an invisible box of its size keeps that place in the page, so nothing moves when it comes alive; an element larger than the canvas is shrunk to fit, with one warning (`fit` scales it like a picture, without one). Its own background and `border-radius` are the outline. It is printed again only when its rendering changes, so a resting card draws nothing; while prints keep coming, `stats().mode` is `'html'`. The focus and the selection inside the element survive the move into the canvas and back. Without the feature, in the static tier, or without WebGL2 the element stays where it is as plain HTML (`mode: 'static'`, no warning); a browser that has the feature but gives no picture within 4 s gets the same fallback with one warning. `handle.element`; `snapshots` in `stats()`. New file `src/live.js`; `examples/live.html`; a live-HTML card in the gallery; `SilkHtml` for React and Next.js in `examples/react` and `examples/next`. Ignored in element mode: `matte`, `threshold`, `corner`, `albedo`, `grain`, `poster`. See SKILL.md step 5.
- `scripts/shoot.mjs` checks live HTML in Chrome (selection and copy, double-click, link, button, typing and an input method, scrolling, the caret, resizing, ripples, sleeping, the fallbacks, `dispose()`); `--browsers` checks the plain-HTML fallback in WebKit and Firefox; `scripts/frameworks.mjs` checks `SilkHtml` under StrictMode.

**Changed**
- **Code that cannot be loaded says so.** A three.js that cannot be resolved (a missing import map), a worker that does not start, or a `core.js` that cannot be imported now logs one `console.warn` naming the cause and the fix, for a picture and an element alike. Before, the mount ended in a still frame or plain HTML with a `reason` and a silent console, and with live HTML the fallback looked exactly right, so the mistake went unseen. Missing features (no WebGL2, the static tier, reduced motion, no HTML-in-Canvas) stay quiet.

**Fixed**
- **`dispose()` while the renderer is starting settles `ready`.** Called in the first moments after `silkify()` (React StrictMode's first mount does exactly that), `ready` never settled; it now resolves with `mode: 'disposed'`, as the handle table always said. This was in 0.2.x too, for pictures.
- `examples/next` is pinned to Next.js 16.4.6: 16.4.2 has a known vulnerability, and its own CLI refuses to build with it.

Pictures look the same: the posters re-render byte for byte.

## 0.2.1 (2026-10-21)

Fixes from an adversarial review of 0.2.0. Every change below is checked by `scripts/shoot.mjs`, `--browsers` or `scripts/frameworks.mjs`, which CI now runs on every push.

**Fixed**
- An SVG picture rendered a blank canvas reported as `'static'`, with no message. SVG is now rasterised on the page (1024 px on its long side) and goes live like any picture.
- A picture that could not be loaded or decoded, or had nothing opaque in it, also ended silently. It is now `mode: 'failed'` with `handle.reason` and one `console.warn`, the library's only console output.
- From the CDN, Safari and Firefox rendered on the main thread instead of in the worker (and Firefox logged a Security Error). Checked in Safari 26.5, the iOS 26.4 Simulator, Firefox 157, WebKit 27.2 and Chrome 156.
- `setTheme()`, `setPhase()` and `ripple()` called before `ready` were dropped.
- `ready` never settled for a canvas in `display: none` that was disposed, nor did `stats()` after `dispose()`; both now settle with `mode: 'disposed'`.
- The React component in SKILL.md broke on its second `src` and blanked the page on unmount; the Vite `threeUrl` line no longer resolved; Next.js 16 with Turbopack did not build. The new component creates its canvas in the effect, bundlers need no configuration, and `examples/react` and `examples/next` are checked in Vite 8 and Next 16, dev and build.
- Moving or holding the pointer anywhere on the page woke every visible object at 60 fps. Only the pointer over the canvas counts now.
- Ripples ran twice as fast on a 120 Hz display. The wave solver steps at a fixed 60 Hz.
- WebGL2 was probed with a throwaway context on the main thread: 2.5 s per page on a software GPU (Lighthouse 69, TBT 9.7 s). It is probed on the canvas itself, in the worker (99, 0 ms).
- Firefox logged two warnings on every mount (a lost context, a deprecated extension).
- `handle.tier` said `'high'` or `'low'` after a fallback to a still frame; it says `'static'`.
- The README's 30-second snippet threw on paste (it mounted a canvas it never declared).
- `cutout.py`: EXIF orientation applied; a note when a wordmark's counters stay opaque (`--no-flood`); one-sentence errors for SVG, HEIC and unreadable files; `--keep-largest` stops instead of doing nothing without scipy.
- Gallery and README descriptions follow their sources (the *Bird figure*, not an "enamel parrot").

**Added**
